# Генератор PDF-накладных

Консольная программа на Python. Она читает чеки из CSV или JSON, подставляет их в HTML-шаблон и сохраняет накладную в PDF. После сохранения файл открывается в программе, которая на компьютере назначена для PDF.

Кириллица печатается шрифтом DejaVu Sans. Скрипт работает на Windows и macOS.

## Что происходит при запуске

1. Программа проверяет, что библиотека WeasyPrint может рисовать PDF.
2. Показывает нумерованный список файлов из папки `data` и шаблонов из папки `templates`.
3. Просит выбрать номер файла данных и номер шаблона.
4. Читает выбранный файл и показывает чеки по `invoice id`.
5. По выбранному номеру собирает HTML: одна строка шаблона превращается в строки товаров.
6. Считает сумму каждой строки, итог и НДС 20%. НДС уже входит в итог, а не прибавляется сверху.
7. Сохраняет PDF в `output` и открывает его.

Пример меню:

```text
================================================
  Генератор PDF-накладных
================================================

Доступные файлы с данными:
  1. csvsource.csv
  2. invoices.csv
  3. invoices.json

Доступные шаблоны:
  1. invoice.html

Номер файла данных: 2
Номер шаблона: 1

Доступные чеки в invoices.csv:
  1. 2026-0007  (5 поз., 07.10.2026)
  2. 2026-0014  (3 поз., 12.10.2026)
  3. 2026-0021  (3 поз., 15.10.2026)

Номер чека (invoice id): 1
```

Если ввести не номер из списка, вопрос повторится. Выход из программы по Ctrl+C.

## Структура проекта

```text
main.py                 программа: меню, чтение данных, сборка PDF
requirements.txt        список Python-пакетов
README.md               это описание
prompt.txt              исходное задание

data/                   исходные данные
  invoices.csv          несколько чеков в одной таблице
  invoices.json         несколько чеков списком объектов
  csvsource.csv         одна таблица товаров без номера чека

templates/
  invoice.html          HTML-шаблон накладной

fonts/
  DejaVuSans.ttf        обычный шрифт
  DejaVuSans-Bold.ttf   жирный шрифт

output/                 сюда программа кладёт готовые PDF
```

Файлы `template.html` и `csvsource.csv` в корне — исходные образцы задания. Программа их не читает. Рабочие копии лежат в `templates` и `data`.

Папки ищутся рядом с `main.py`, а не относительно текущей папки терминала. Скрипт можно запускать из любого каталога.

## Установка

Нужен Python 3.10 или новее.

Из папки проекта:

```text
pip install -r requirements.txt
```

В файле требований две библиотеки:

- `pandas` читает CSV;
- `weasyprint` превращает HTML в PDF.

JSON читается стандартным модулем `json`, его устанавливать не нужно.

Этого мало для PDF. WeasyPrint рисует текст через системную библиотеку Pango. Её ставят отдельно, и команда зависит от системы.

### Windows

1. Установите [MSYS2](https://www.msys2.org/) с настройками по умолчанию. Обычно он оказывается в `C:\msys64`.
2. Откройте оболочку **MSYS2 UCRT64** из меню Пуск. Это не PowerShell и не обычный cmd.
3. В UCRT64 выполните:

```bash
pacman -S mingw-w64-ucrt-x86_64-pango
```

4. Закройте UCRT64. Дальше работайте в PowerShell или cmd, в папке проекта.

Если Pango установлен в `C:\msys64\ucrt64\bin`, `main.py` находит эту папку сам. Переменную окружения задавать не нужно.

Если библиотеки лежат в другом месте, укажите папку в том же окне, где запускаете Python. Команда `set` работает только в cmd. В оболочке UCRT64 её запускать не нужно: Python из неё обычно не вызывают.

PowerShell:

```powershell
$env:WEASYPRINT_DLL_DIRECTORIES = "C:\msys64\ucrt64\bin"
python main.py
```

cmd.exe:

```bat
set WEASYPRINT_DLL_DIRECTORIES=C:\msys64\ucrt64\bin
python main.py
```

Такая переменная живёт только до закрытия окна. В новом окне её задают снова, либо полагаются на автопоиск стандартной папки.

### macOS

Установите Pango через Homebrew, затем пакеты Python:

```bash
brew install pango
pip install -r requirements.txt
python3 main.py
```

## Запуск

Windows:

```text
python main.py
```

macOS:

```text
python3 main.py
```

Готовый файл называется `output/nakladnaya-<номер>.pdf`. Например, чек `2026-0007` сохраняется как `output/nakladnaya-2026-0007.pdf`.

## Как устроены данные

Программа понимает русские и английские имена полей. Регистр и пробелы не важны: `Invoice ID`, `invoice-id` и `invoice_id` — одно и то же поле.

Номер чека ищется в `invoice_id`, `invoiceid`, `invoice`, `id`, `номер`.
Дата — в `date`, `invoice_date`, `дата`.
Товар — в `product`, `name`, `товар`, `наименование`.
Цена — в `price`, `цена`.
Количество — в `quantity`, `qty`, `количество`, `кол-во`.

Дата может быть записана как `07.10.2026`, `2026-10-07` или `07/10/2026`. В PDF она всегда выводится как `07.10.2026`.

Сумму строки, итог и НДС в файл класть не нужно. Программа считает их сама.

НДС считается как налог внутри суммы: `итог * 0.20 / 1.20`. Для суммы 120 рублей это 20 рублей, а не 24.

### CSV

Один чек занимает несколько строк: по строке на товар. Строки с одинаковым `invoice_id` собираются в одну накладную.

```csv
invoice_id,date,product,price,quantity
2026-0007,07.10.2026,Яблоки,120.50,10
2026-0007,07.10.2026,Бананы,89.90,25
2026-0014,12.10.2026,Тетрадь 48 л.,35.00,40
```

Файл сохраняйте в UTF-8. Кодировка `utf-8-sig` тоже подходит: это UTF-8 с меткой, которую иногда добавляет Excel.

Если колонки `invoice_id` нет, весь файл становится одним чеком. Номером будет имя файла без расширения. Так устроен `data/csvsource.csv`: в меню он виден как чек `csvsource`.

### JSON

Обычный вид — список накладных. Товары лежат во вложенном списке `items`. Имя `products` или `lines` тоже принимается.

```json
[
  {
    "invoice_id": "2026-0030",
    "date": "01.10.2026",
    "items": [
      {"product": "Сыр Российский", "price": 620.00, "quantity": 4},
      {"product": "Масло сливочное", "price": 180.00, "quantity": 10}
    ]
  }
]
```

Ещё два допустимых вида:

- обёртка `{"invoices": [ ... ]}`;
- объект, где ключ — номер чека: `{"2026-0030": {"date": "...", "items": [ ... ]}}`;
- плоский список строк, как в CSV: у каждой записи есть `invoice_id`, `product`, `price` и `quantity`.

## HTML-шаблон

Шаблон — обычный HTML-файл в папке `templates`. Программа берёт все файлы `.html` и `.htm`.

В шаблоне должна быть одна строка таблицы `<tr>`, внутри которой есть метка `{{ product }}`. Эта строка копируется по одному разу на каждый товар. Остальная вёрстка остаётся как есть.

Метки, которые программа заменяет:

| Метка | Откуда берётся |
| --- | --- |
| `{{ n }}` | порядковый номер строки, начиная с 1 |
| `{{ product }}` | название товара |
| `{{ price }}` | цена |
| `{{ quantity }}` | количество |
| `{{ sum }}` | цена × количество |
| `{{ invoice_id }}` | номер чека |
| `{{ date }}` | дата или тире, если даты нет |
| `{{ total }}` | итог |
| `{{ vat }}` | НДС 20% внутри итога |
| `{{ items_count }}` | сколько товарных строк |

Деньги выводятся с двумя знаками после точки и пробелом между тысячами: `6 682.00`. Целое количество выводится без дроби: `10`, а не `10.00`.

Название фирмы, реквизиты поставщика и покупателя в `templates/invoice.html` записаны прямо в HTML. Их программа из файла данных не подставляет. Чтобы изменить шапку, правьте шаблон.

Шрифт подключён в начале `<style>` через `@font-face` и файлы из папки `fonts`. Перед генерацией программа заменяет относительный путь на полный `file://...`, чтобы WeasyPrint открыл шрифт даже если путь к проекту содержит пробелы.

Новый шаблон можно положить рядом с `invoice.html`. Он появится в меню под следующим номером. В нём тоже нужна строка с `{{ product }}`. Если `@font-face` нет, программа допишет DejaVu Sans сама.

## Где смотреть код

Весь сценарий находится в `main.py`. Комментарии написаны рядом с кодом. Крупные части такие:

- `Item` и `Invoice` хранят одну строку и одну накладную. Сумма и НДС считаются свойствами, а не хранятся в файле.
- `load_csv` и `load_json` приводят разные файлы к одному списку накладных.
- `render_html` копирует строку таблицы и подставляет метки.
- `write_pdf` вызывает WeasyPrint.
- `main` показывает меню и связывает шаги.

## Если что-то пошло не так

**В консоли сообщение про `libgobject` или Pango.** Python-пакет WeasyPrint установлен, а системные библиотеки — нет. На Windows поставьте Pango через MSYS2 UCRT64, как в разделе установки. На macOS выполните `brew install pango`. Команду `set` не запускайте внутри UCRT64.

**В меню нет файлов.** CSV и JSON должны лежать в `data`, шаблоны — в `templates`. Файл в корне проекта программа не видит.

**В шаблоне нет строки с `{{ product }}`.** Программа не знает, какой кусок HTML повторять для товаров, и останавливается с этой ошибкой.

**В PDF вместо русских букв пустые квадраты.** В папке `fonts` должны быть `DejaVuSans.ttf` и `DejaVuSans-Bold.ttf`. В CSS шаблона у `body` должен быть шрифт `"DejaVu Sans"`.

**PDF сохранился, но не открылся.** Файл уже лежит в `output`. Откройте его вручную. Автоматическое открытие — отдельный шаг после записи.
